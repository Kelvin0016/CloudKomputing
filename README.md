# docker-cicd

Terraform-provisioned AWS infrastructure and a small Flask app, deployed
automatically via GitHub Actions on every push. Built as part of a personal
cloud security / DevSecOps study plan (Phase 5: Docker, CI/CD, IaC security).

This branch is kept as pure infrastructure code — documentation, notes, and
certificates live on `main` instead.

## Infrastructure (terraform-docker-host/)

Provisions, in `ap-southeast-5` (AWS Malaysia):

- **EC2 instance** (t3.micro, Amazon Linux 2023) — the Docker host
  - IMDSv2 enforced, root volume encrypted
  - `user_data` auto-installs and starts Docker on first boot, so the
    instance is self-bootstrapping after any replacement
  - `lifecycle { ignore_changes = [ami] }` — won't be destroyed/recreated
    just because AWS publishes a newer AMI
- **Security group** — SSH (22) and the app port (5000) restricted to the
  caller's current public IP, auto-detected at `terraform apply` time via
  the `http` provider
- **Lambda function** — checks the instance's runtime every 15 minutes
  (via EventBridge Scheduler) and auto-stops it after 4 hours, so it's
  never accidentally left running
- **Key pair** — generated by Terraform; the private key is written locally
  and is gitignored, never committed

Run it:
```bash
cd terraform-docker-host
terraform init
terraform plan
terraform apply
```

Scan it (Trivy, tfsec's ruleset successor — see
`terraform-docker-host/SECURITY_ACCEPTED_FINDINGS.md` for what's fixed vs.
consciously accepted):
```bash
trivy config .
```

## App (flask-app/)

A minimal Flask app, containerized. `host="0.0.0.0"` is required in
`app.py` so the container is reachable outside itself.

## CI/CD (.github/workflows/deploy.yml)

Triggers on push to `docker-cicd`, scoped to changes under `flask-app/`.

The pipeline authenticates to the EC2 instance over SSH, but doesn't leave
port 22 open to the internet or to GitHub's IP ranges. Instead, each run:

1. Fetches its own runner's public IP
2. Temporarily authorizes just that IP on the security group
3. Copies the app files over and rebuilds/restarts the Docker container
4. Revokes that IP rule again (`if: always()`, so cleanup runs even if a
   step fails)

Uses a dedicated, least-privilege IAM user (`github-actions-deploy`) —
scoped to only `AuthorizeSecurityGroupIngress`, `RevokeSecurityGroupIngress`,
`DescribeSecurityGroups`, `DescribeInstances` — not an admin credential.

### Required GitHub Secrets

| Secret | Value |
|---|---|
| `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` | `github-actions-deploy` IAM user |
| `AWS_REGION` | `ap-southeast-5` |
| `EC2_INSTANCE_ID` | Current instance ID — **update after any Terraform replacement** |
| `EC2_SG_ID` | The security group ID |
| `EC2_SSH_KEY` | Full contents of the `.pem` private key |
| `EC2_USER` | `ec2-user` |

`EC2_INSTANCE_ID` is the one thing that goes stale: any Terraform change
that forces instance replacement (e.g. changing `encrypted` on the root
volume) gives the instance a new ID, and the secret needs updating to match.

## Known accepted risk

Unrestricted egress (`0.0.0.0/0`) on the security group — the host needs
outbound access to Docker Hub, dnf mirrors, and GitHub, which don't have
stable IP ranges to allowlist. Ingress stays tightly scoped. Full reasoning
in `terraform-docker-host/SECURITY_ACCEPTED_FINDINGS.md`.
